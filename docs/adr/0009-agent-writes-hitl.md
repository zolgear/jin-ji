# ADR-0009: AI エージェントによる書き込み（公開に至る変更は人が承認する）

- ステータス: **承認**（決定 2 は 2026-10-30 に [ADR-0013](0013-field-managed-changes.md) で改めた）
- 日付: 2026-10-18
- 関連: [ADR-0004](0004-authentication.md)、[ADR-0006](0006-mcp-sdk.md)、[ADR-0008](0008-authorization-model.md)、[アーキテクチャ概要 §7.1・§7.3](../architecture/overview.md#71-ai-エージェントによる書き込み)、[ADR-0013](0013-field-managed-changes.md)（現場の直接登録。決定 2 を改めた）

## 決定

1. **境目は「公開される情報に影響するか」とする。** 公開される情報（社内への表示・API・配信・外部同期）に影響する書き込みは、変更提案として登録するまでをエージェントに許し、人の承認で反映する。承認の関門より手前の作業領域には、エージェントが承認なしで書き込んでよい。

   | 区分 | 例 | エージェントの書き込み |
   | --- | --- | --- |
   | 公開される情報 | 在籍者・組織・所属・役職・連絡先、公開範囲のポリシー、社内システムへの配信、Entra ID への同期計画の確定 | 変更提案として登録するまで |
   | 公開されない作業領域 | 取込データの正規化、名寄せの候補、要確認の提案への推定、提案の下書き | 自動で書き込んでよい |

2. **公開側の値を直接変えるツールは MCP に持たせない。** 公開側の正は人事パッケージで（ADR-0002）、jin-ji の公開側を変えるのは取込の変更提案の承認だけ。エージェントが書けるのは、要確認の提案への推定（作業領域）と、修正依頼の起票（人事パッケージで直せる人への情報提供。jin-ji の公開データは変えない）だけ。
   - **ADR-0013 で改めた**: 公開側への入口に、人（範囲を持つ組織長・指名した担当・`org_admin`・人事管理者）の直接登録を加えた。エージェントは直接登録とグループ（[ADR-0014](0014-informal-groups.md)）の変更の下書きまでを作れ、反映は委任元の人の確定の操作だけが行う。素案（シミュレーション）は作業領域なので、承認なしで書ける
3. **承認・管理の操作はエージェントにさせない。** そのためのスコープを作らない（`jinji.read`・`jinji.propose` だけ。ADR-0004）。
4. **エージェントの提案は委任元の人の起案として扱う。** 職務分掌の対象の操作では、委任元は自分の提案を承認できない。
5. 自動の書き込みも、監査ログ（委任元・エージェント・クライアント）とレート制限の対象にする。LLM による候補提示（ADR-0005）も同じ扱いで、作業領域の根拠に書くだけにする。

## 背景

- jin-ji の目的は人事情報を AI エージェントから安全に扱えるようにすることで、エージェントの書き込みを全面的に禁じると、名寄せや正規化のような手間の大きい作業を任せられない
- 一方で、エージェントはプロンプトインジェクションや誤推定の影響を受ける。公開される情報が汚れると、社内システムや Entra ID に誤りが広がる

## 検討した選択肢

| 案 | 評価 |
| --- | --- |
| A. エージェントは読み取りだけ | 安全だが、取込・名寄せの作業を任せられない |
| B. すべての書き込みに人の承認を要求する | 作業領域の下書きまで承認が要り、少人数の運用（概要 §1）で回らない |
| **C. 公開に影響するかで分ける** | 採用。作業領域は誤っても公開側に出ない |
| D. 権限の範囲でエージェントに直接の更新を許す | 誤りがそのまま配信・同期に流れる。正は人事パッケージなので、jin-ji で直す意味も薄い |

## 帰結

- エージェントが作業領域で誤っても、公開される情報は汚れない。人は承認画面で根拠（取込元の行・確信度・エージェントの推定）を見て判断する
- 承認の手間は残る。承認画面と一覧で、まとめて確かめられるようにする
- ツールの一覧と実装の規則は [概要 §7.3](../architecture/overview.md#73-mcp-サーバーの実装の規則)
