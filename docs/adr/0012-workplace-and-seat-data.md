# ADR-0012: 建物・階・座席と、人の席・所在の扱い

- ステータス: **提案**
- 日付: 2026-10-18
- 関連: [ADR-0002](0002-data-scope.md)（扱うデータの範囲）、[建物・フロアモードの仕様と実装方針](../design/building-floor-mode.md)、[アーキテクチャ概要 §4.7・§5](../architecture/overview.md)

## 決定（案）

1. **建物・階・簡易フロアマップ（外形・ゾーン・席の置き場所）と、人の席（固定席・持ち場・ホームエリア）を、全社公開レベルの情報として保持する。** 社内に掲示される座席表と同じ水準とみなす。ADR-0002 の「保持する項目」の拠点の行に「建物・階・エリア・座席、人の席（有効期間付き）、組織のホームエリア」を足す
2. **座席データの正は、導入先ごとに「jin-ji」か「外部の施設管理・座席予約システム」のどちらか一方に決める。** 人事パッケージは座席を持たないことが多いため、jin-ji を正にする場合、jin-ji が正になる初めての情報になる。外部を正にした導入先では、jin-ji は取り込むだけにして編集の画面を閉じる（二重管理をしない）
3. **当日の所在（予約・チェックイン・入退館・測位）は、この ADR では保持しない。** 必要になったら別の ADR で、自己申告の予約だけ・短い保持・狭い既定の公開範囲・個人別レポートなしの枠（仕様 §3.4）を前提に決める
4. **簡易フロアマップは、手で描ける・CSV / JSON で書ける形（整数のミリメートルの座標、多角形・点・既定の机の型）に限る。** CAD・BIM・図面画像・SVG は取り込まない（SVG は表示と書き出しにだけ使う）
5. **将来の席の割り当て（席替えの予定）は、内示と同じ線で人事管理者以外に見せない。**

## 背景

- 3D 表示で拠点を「組織の属性」ではなく「物理的な建物」として扱い、人がどの階・どの席にいるかを把握・管理したいという要望がある（一般社員の同僚探し、総務の座席管理、人事の席替えの計画、AI エージェントへの問い合わせ）
- ADR-0002 は全社公開レベルの情報だけを持つと決めている。固定席は座席表として社内に公開されることが多い一方、当日の所在は行動の記録で、従業員のモニタリングとして受け取られやすい
- jin-ji は人事情報の正ではない（ADR-0002 の決定 1）。座席のマスタには人事パッケージという正が無く、正の置き場所を決めないと二重管理になる

## 検討した選択肢

| 案 | 概要 | 評価 |
| --- | --- | --- |
| A. 固定席だけ（当日の所在なし） | 建物・階・座席と、有効期間付きの席の割り当て | **採用（案）**。全社公開レベルに収まり、ADR-0002 の考え方を崩さない |
| B. 固定席 + 自己申告の座席予約 | A に当日の予約（本人の操作だけ）を足す | 有用だが、ADR-0002 の範囲を超える。別の ADR で、保持・公開範囲の枠とともに決める |
| C. 入退館・測位まで取り込む | IC カード・Wi-Fi / BLE の記録から所在を出す | 不採用。本人の操作によらない行動の記録で、監視と受け取られ、勤怠への転用の恐れがある |

## 帰結

### 良い点

- 「〇〇さんの席は？」「3 階の空席は？」に、人・AI エージェントが同じ権限判定で答えられる
- 席の割り当てを有効期間で持つので、タイムマシンで過去の席配置を見られ、席替えの計画を時点で確かめられる
- 当日の所在を持たないので、監視・勤怠への転用の懸念を設計の段階で避けられる

### 注意点

- 席の粒度は人の所在を細かく示すので、項目を「階・エリア（`workplace`）」と「席（`seat`）」に分け、ポリシーで別々に狭められるようにする
- 個人単位の例外で席を隠した人の席は、閲覧者には「使えない席」（保守中・予備と同じ表示）として見せ、例外があることを目立たせない
- 健康・障害を推測させる席の属性（車椅子対応など）は持たない
- 座席データを jin-ji で正として持つ導入先では、jin-ji に新しい編集の責任（総務の運用・承認）が生まれる。新しいロール（ファシリティ管理者）と職務分掌を足す

## 未決

- ファシリティ管理者に将来の席替えの「誰か」を見せるか（推奨は人を伏せた予定の枠だけ）
- 当日の所在を扱う ADR を起こすか
